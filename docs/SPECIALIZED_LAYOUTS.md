# Guide rapide — layouts spécialisés MARS Design API 1.0

| Layout | Quand l'utiliser | À éviter |
|---|---|---|
| `architecture` | modèle composé de blocs ou couches | simple pipeline de 3 étapes (`diagram`) |
| `algorithm` | procédure, pseudo-code, boucle d'optimisation | définition mathématique statique |
| `math-derivation` | calcul en plusieurs étapes | une seule formule (`equation-focus`) |
| `timeline` | évolution historique | séquence causale non temporelle |
| `gallery` | plusieurs exemples visuels comparables | un visuel unique dominant |
| `experiment` | résultat, benchmark, métrique | galerie descriptive |
| `motivation` | ouvrir une notion par un problème | explication détaillée |
| `question` | rupture pédagogique / question centrale | contenu dense |
| `intuition` | analogie avant formalisme | preuve ou dérivation |
| `take-home` | synthèse de section | liste longue de détails |

## Choix entre `diagram` et `architecture`

- `diagram` : flux conceptuel simple, généralement 3–5 étapes.
- `architecture` : structure d'un modèle, couches/blocs, vocabulaire technique.

## Choix entre `figure-full`, `gallery` et `experiment`

- `figure-full` : une image porte presque tout le message.
- `gallery` : plusieurs exemples ont le même statut.
- `experiment` : une figure est accompagnée d'une observation ou métrique principale.

## Choix entre `motivation`, `question` et `intuition`

- `motivation` : pourquoi le sujet mérite d'être étudié ?
- `question` : quelle question allons-nous résoudre maintenant ?
- `intuition` : comment comprendre mentalement l'idée avant les équations ?
